# ADR-0001：采用本地优先的 TypeScript 单机运行时

- 状态：已接受
- 日期：2026-10-24

## 背景

目标产品需要同时覆盖本地 CLI、桌面端、HTTP/WebSocket 控制面、stdio Agent 进程和多种 webhook 渠道。个人电脑长期运行要求安装和升级成本低、故障范围小、数据可导出。过早引入多个服务和多种语言会增加部署、调试和迁移成本。

## 决策

第一阶段使用 Node.js 22、TypeScript 严格模式和 pnpm workspace，核心以模块化单进程本地运行时交付。领域层与适配器层隔离，未来将高风险执行器或性能热点拆为 Rust/容器服务。桌面端使用 Tauri 2 作为后续控制面包装，不让 UI 直接拥有 Agent 执行权限。

## 结果

- 可以共享类型和事件模型，CLI、桌面端与渠道使用同一个本地 API。
- 进程/stdio、JSONL、HTTP、WebSocket 生态接入成本较低。
- 需要严格控制 Node 进程权限，不能把“单进程”误认为“安全沙箱”。
- 沙箱、密钥链和系统集成需要平台特定实现或独立执行器。

## 放弃的方案

- 一开始采用微服务：不适合单机优先和长期维护目标。
- 一开始全部采用 Rust：可以获得更强的系统控制，但会降低首阶段适配器、CLI 和 UI 迭代速度。
- 直接绑定某家 Agent SDK：会破坏供应商中立和兼容性诚实原则。
