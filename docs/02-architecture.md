# AgentCorps 技术架构

> 版本：0.1.0
> 目标：先形成稳定的本地核心，再逐步增加桌面端、渠道和高级生态能力。

## 1. 技术选型

### 1.1 总体方案

采用 **TypeScript + Node.js 22 + pnpm workspace** 作为第一阶段主技术栈：它适合同时构建本地守护进程、CLI、HTTP/WebSocket API、进程/stdio 适配器和桌面端桥接。桌面端计划采用 Tauri 2，将前端 UI 与本地运行时分离；如果后续需要更强的系统沙箱或高性能执行器，再将执行器拆成 Rust 服务，而不是一开始把整个产品拆成多语言分布式系统。

### 1.2 数据层

- SQLite：本地元数据、任务、事件索引、审批、审计和记忆元数据。
- append-only event log：事件以版本化 JSON 存储，SQLite 负责索引和事务。
- 文件系统：大型输出、附件和导出包使用内容寻址文件存储。
- 检索：第一阶段关键词/字段检索；第二阶段可插入 SQLite FTS5 或本地向量索引，向量库必须可替换。
- 密钥：优先使用 macOS Keychain、Windows Credential Manager、Linux Secret Service；开发环境才允许受保护文件回退。

### 1.3 API 与通信

- 本地控制面：HTTP REST + WebSocket/SSE。
- Agent 进程：stdio JSONL 优先，支持超时、背压、最大帧大小和退出检测。
- MCP：独立 MCP 客户端适配层，向核心暴露统一的 Tool/Resource/Prompt 能力。
- 外部渠道：webhook 入站 + 发送 API 出站，通过签名校验、幂等键和限流。
- 远程访问：默认关闭；用户开启后使用短时、可撤销、最小权限的访问令牌和只读视图。

## 2. 分层

### Domain

只包含 ID、值对象、命令、事件、状态机和策略接口，不依赖 Node、数据库、供应商 SDK 或 UI。

### Runtime

负责任务编排、运行生命周期、事件追加、恢复、取消、重试、审批和资源配额。运行时通过端口（ports）调用 Agent、存储、时钟、密钥和沙箱实现。

### Adapters

将外部 Agent、MCP 服务、插件包、技能包、聊天渠道和系统执行器转换为平台端口。适配器必须提供能力探测、版本信息和健康状态。

### Interfaces

CLI、桌面 UI、本地 API、远程只读 UI 和聊天渠道都是控制面客户端，不直接操作数据库或运行 Agent。

## 3. 任务执行模型

1. 用户或渠道提交 `CreateTask` 命令。
2. 运行时验证工作区、模式、策略和输入，写入 `TaskCreated`。
3. 调度器创建一次 `Run`，选择 Agent/模型/工具能力并写入 `RunStarted`。
4. Agent 输出、工具调用、审批请求和子任务都转成事件。
5. 策略引擎在工具执行前检查能力、范围、风险、预算和审批要求。
6. 运行以成功、失败、取消、超时或等待审批结束，并记录检查点。
7. 事件投影器更新任务视图，所有客户端从事件流获得进度。

## 4. 记忆模型

记忆不是隐藏的全局文本，而是具有以下字段的实体：`memoryId`、`scope`、`workspaceId`、`content`、`sourceEventId`、`confidence`、`sensitivity`、`createdAt`、`updatedAt`、`expiresAt`、`deletedAt`。默认只在同范围检索；跨工作区检索必须显式授权。自动提取的记忆先进入候选区，只有满足策略或经过用户确认才升级为持久记忆。

## 5. 模式

- **code**：默认工作区为代码仓库；允许读取代码、运行受限测试和生成补丁；写入、网络、凭据和发布动作按风险审批。
- **work**：默认处理办公文档、消息和结构化资料；外发消息、删除、提交审批和访问敏感数据必须人工确认。

模式只是一组可版本化的策略、提示模板和工作流默认值，不是绕过安全边界的开关。

## 6. 可演进边界

A2A、特定供应商 SDK、实验性桌面自动化和远程执行器放在 `adapters/experimental` 或单独包中。核心只依赖标准化的任务、消息、能力、事件和审批接口。这样可以在协议过时、供应商改版或安全风险出现时替换适配器，而不破坏已有会话和记忆。
